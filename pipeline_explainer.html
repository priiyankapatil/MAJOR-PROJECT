Agriculture RAG Pipeline: Full Runtime Explainer

This document explains what runs when you start step6_query_gate.py, how a question moves through the pipeline, what each major file does, and where the regulatory compliance layer fits in. Knowledge graph and trust scoring are intentionally skipped.

Startup update Semantic bridge Entropy routing Hybrid retrieval Temporal filter Phenology gate Weather enrichment Sentence provenance Regulatory compliance

1. Big Picture

The system is a multi-stage agricultural question-answering pipeline. A user asks a query, the system enriches it with local scientific terms, decides whether the question is simple or complex, retrieves source chunks, filters stale content, optionally adds weather and seasonal context, generates an answer, maps sentences back to sources, and then runs a pesticide compliance check.

The current working setup includes the regulatory modules and the compliance scan. The knowledge graph and trust-scoring paths are not part of this explanation.

3. Startup: What Happens First

Step A: Load environment
The script now loads .env before importing the regulatory updater, so API keys are available in-process.
Step B: Regulatory auto-update
The updater runs freshness checks, tries CIB&RC and EU scrapes, and can do online verification for borderline pesticides.
Step C: Search stack loads
ChromaDB, BM25, and the embedding model are loaded after the regulatory startup phase.

4. Query-Time Flow

Step 0: Semantic bridge
Maps folk/local terms to scientific crop terms using the bridge modules.
Step 1: Classification
Determines whether the query is factual, diagnostic, recommendation, etc.
Step 2: Entropy routing
Measures uncertainty and selects fast path or slow path.

5. Retrieval and Answering

Once the route is chosen, the system retrieves candidate chunks from the vector store and BM25 corpus. Those chunks then pass through temporal credibility filtering so old sources are reduced or removed. If the query is crop-related, the phenological gate checks whether the advice fits the crop stage and season. Weather data is injected when the query needs live environmental context.

Hybrid retrieval Temporal decay Phenological gating Weather-aware advice

6. Answer Output

The final answer is produced by Groq. Fast path uses the gate model; slow path uses the stronger answer model. After generation, the answer goes through provenance and compliance checks before it is printed.

7. Files and Their Roles

step6_query_gate.py

Main runtime orchestrator. It loads env vars, starts the regulatory updater, processes queries, retrieves chunks, generates the answer, and prints final output.

semantic_bridge.py

Normalizes rural or dialect phrasing into scientific crop/agriculture terminology. Helps retrieval match the right knowledge.

adaptive_entropy.py

Maintains entropy thresholds and records feedback so routing can adapt over time.

temporal_credibility.py

Filters stale chunks so outdated advice is less likely to reach the answer model.

phenology_gate.py

Checks whether a recommendation matches the crop stage or season before the chunk is used.

step8_weather_rag.py

Adds live weather context when the query is a recommendation or diagnosis and weather is relevant.

sentence_provenance.py

Maps answer sentences back to source chunks and reports confidence for traceability.

regulatory_kb.py

Static pesticide knowledge base: WHO hazard, India status, EU risk, organic status, PHI, MRL, and alternatives.

compliance_scanner.py

Detects pesticide mentions in the answer, scores them, and builds the compliance warning box.

regulatory_updater.py

Live regulatory updater that checks freshness, scrapes public sources, does Tavily + Groq verification, and manages the dynamic KB.

8. Regulatory Compliance Layer

This is the new Module 7/7B layer. It is designed to be conservative:

  • The answer is scanned for pesticide names.
  • Each pesticide is scored using WHO, India, EU, and organic penalties.
  • If no pesticide is found, no warning box is printed.
  • If pesticides are found, the regulatory report is appended to the answer.
  • If borderline pesticides are found, the updater can verify them asynchronously.
The updater only overrides the static KB when it gets strong enough online evidence. If Tavily/Groq evidence is weak, the system intentionally falls back to the static KB.

9. Why the Confidence Gate Exists

The online verifier is intentionally strict. If the search results do not explicitly show pesticide-specific regulatory evidence, the dynamic result is rejected and the static KB remains authoritative. That is why you sometimes see:

Confidence : 0.10 Verified : False Source URL : None

This is not a failure. It is a safety rule that prevents the system from overwriting known regulatory data with weak web evidence.

10. Example Runtime Sequence

  1. User runs python step6_query_gate.py.
  2. The script loads .env and starts the regulatory updater.
  3. The updater checks KB freshness and tries live scrapes; if unavailable, it falls back safely.
  4. The search components load and the query loop starts.
  5. The user asks a question.
  6. The semantic bridge normalizes the query.
  7. The classifier decides fast or slow path.
  8. The retriever fetches chunks and the temporal/phenology/weather steps refine them.
  9. The answer is generated.
  10. Provenance and compliance steps run.
  11. If pesticides appear, the compliance report is appended.
  12. If needed, borderline pesticide verification starts in the background.
  13. The final answer and sources are printed.

11. How to Check It in Terminal

$env:NO_INTERACTIVE_FEEDBACK='1' python step6_query_gate.py

To test the online regulatory verification path specifically, load your .env and run the Tavily + Groq verification function from regulatory_updater.py.

12. Final Idea in Simple Words

The pipeline is a layered agricultural assistant. It does not just answer from a model. It first understands the question, looks up evidence, filters bad sources, adds weather and seasonal context when useful, and then applies a regulatory safety check before showing the result. The regulatory layer is there to prevent unsafe pesticide advice from being returned without warning.
